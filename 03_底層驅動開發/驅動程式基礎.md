## 📌 Context: 什麼是驅動程式？

**驅動程式 (Driver)** 是 "User Space Application" 與 "Hardware" 之間的翻譯官。

-   **User Space**: 只懂標準檔案操作 (`open`, `read`, `write`, `ioctl`)。
-   **Hardware**: 只懂暫存器讀寫、中斷訊號。
-   **Driver**: 將 `write("Hello")` 翻譯成 `writel(0x48, REG_TX_DATA)`。

**為什麼要分成 User/Kernel Space？**
為了**安全**與**穩定**。硬體操作權限被鎖在 Kernel Space，應用程式必須透過 "System Call" 請求 Kernel 代勞，防止隨意寫入暫存器導致系統崩潰。

## 🧠 Mental Model (核心觀念圖解)

### 1. 驅動開發的三角形：Bus-Device-Driver

Linux Device Model 的核心哲學：將「硬體描述」與「驅動邏輯」分離。

```text
       match() ?
      ┌─────────┐
      │   Bus   │  (e.g., Platform, I2C, SPI)
      └────┬────┘
           │
     ┌─────┴─────┐
     ▼           ▼
┌────────┐   ┌────────┐
│ Device │   │ Driver │
│ (Hardware) │ (Software) │
└────────┘   └────────┘
    ↑            ↑
  DTS描述       C代碼
(資源: IRQ,Reg) (邏輯: probe)
```

-   **Bus**: 媒人。負責遍歷 Device 和 Driver，若名字匹配 (Compatible)，就呼叫 Driver 的 `probe()`。
-   **Device**: 有什麼硬體？(Resources)。通常由 Device Tree (.dts) 定義。
-   **Driver**: 如何操作？(Logic)。C code 實作。

### 2. VFS 與 Character Device

在 Linux 中，一切皆檔案。

```text
App (open "/dev/myled")
       │
       ▼ (System Call)
      VFS (Virtual File System)
       │
       ▼ (inode -> cdev)
 Character Device (cdev)
       │
       ▼ (file_operations)
 Driver Functions (.open, .write)
       │
       ▼ (iowrite32)
    Hardware
```

## 🔷 Logic I: 現代驅動開發標準 (Platform Driver)

現代嵌入式 Linux (ARM) 驅動，90% 都是 **Platform Driver**。

### 1. 核心結構

```c
/* 定義 Driver */
static struct platform_driver my_driver = {
    .probe = my_probe,    /* 重頭戲：初始化 */
    .remove = my_remove,  /* 清理 */
    .driver = {
        .name = "my-driver",
        .of_match_table = my_of_match, /* 用來匹配 DTS */
    },
};

/* 註冊 Driver 到 Platform Bus */
module_platform_driver(my_driver);
```

### 2. Probe 函式：驅動的入口

當 Bus 發現 Device 和 Driver 匹配時，會執行 `probe()`。現代 Driver 應全面使用 **devm_ API** (Device Managed)。

**標準初始化流程 (Pattern)：**

```c
static int my_probe(struct platform_device *pdev)
{
    struct my_data *priv;
    struct resource *res;
    int irq, 

    /* 1. 分配私有結構 (devm_kzalloc 自動釋放) */
    priv = devm_kzalloc(&pdev->dev, sizeof(*priv), GFP_KERNEL);
    if (!priv) return -ENOMEM;

    /* 2. 獲取並映射暫存器 (devm_ioremap_resource) */
    res = platform_get_resource(pdev, IORESOURCE_MEM, 0);
    priv->base = devm_ioremap_resource(&pdev->dev, res);
    if (IS_ERR(priv->base)) return PTR_ERR(priv->base);

    /* 3. 獲取中斷號 */
    irq = platform_get_irq(pdev, 0);
    
    /* 4. 註冊中斷 (devm_request_irq) */
    ret = devm_request_irq(&pdev->dev, irq, my_handler, 0, "my-dev", priv);
    if (ret) return ret;

    /* 5. 保存私有數據供其他函數使用 */
    platform_set_drvdata(pdev, priv);

    return 0;
}
```

### 3. Deferred Probe 機制

**問題**：如果你的 Driver 需要使用的資源 (如 Clock, Regulator, GPIO) 的 Driver 還沒載入怎麼辦？
**解法**：資源 API (如 `devm_clk_get`) 會回傳 `-EPROBE_DEFER`。Kernel 看到這個錯誤碼，會把你的 Driver 放到 "Pending List"，等一下再重試 probe。

```c
    priv->clk = devm_clk_get(&pdev->dev, NULL);
    if (IS_ERR(priv->clk)) {
        /* 如果是 EPROBE_DEFER，這是正常現象，不是 Error */
        return PTR_ERR(priv->clk); 
    }
```

## 🔷 Logic II: 使用者介面實作

### 1. Character Device (cdev)

這是最傳統的介面，適合資料流 (Data Stream) 裝置。

```c
/* 定義操作邏輯 */
static const struct file_operations my_fops = {
    .owner = THIS_MODULE,
    .open = my_open,
    .read = my_read,
    .write = my_write,
};

/* 在 probe 中註冊 */
alloc_chrdev_region(...); /* 1. 拿門牌號 (Major/Minor) */
cdev_init(&cdev, &my_fops); /* 2. 初始化 cdev */
cdev_add(&cdev, ...);       /* 3. 加入系統 (User 可以 open 了) */
class_create(...);          /* 4. 讓 udev 自動建立 /dev/node */
device_create(...);
```

### 2. Misc Device (簡化版 cdev)

如果你只想要一個 `/dev/mydevice`，不想管 Major/Minor 和 Class，用 **Misc Device**。

```c
static struct miscdevice my_misc = {
    .minor = MISC_DYNAMIC_MINOR,
    .name = "simple_dev",
    .fops = &my_fops,
};

/* 只需要一行註冊 */
misc_register(&my_misc);
```

### 3. Sysfs Attributes (控制介面)

適合用來設定參數 (Config) 或讀取狀態 (Status)。檔案位於 `/sys/devices/platform/my-dev/...`。

```c
/* Show: 讀取 */
static ssize_t my_show(struct device *dev, struct device_attribute *attr, char *buf) {
    struct my_data *priv = dev_get_drvdata(dev);
    return sysfs_emit(buf, "%d\n", priv->val);
}

/* Store: 寫入 */
static ssize_t my_store(struct device *dev, struct device_attribute *attr, const char *buf, size_t count) {
    /* 解析輸入字串 */
    kstrtoint(buf, 10, &val);
    /* ... */
    return count;
}

static DEVICE_ATTR_RW(my_param); /* 宣告 my_param */
```

## 🔷 Logic III: Driver 同步機制 (Synchronization)

Driver 會被同時 (Concurrently) 存取，必須保護共享數據。

### 1. 鎖的選擇 (Locking Strategy)

| 鎖類型 | 特性 | 適用場景 | Context 要求 |
| :--- | :--- | :--- | :--- |
| **Mutex** (`mutex_lock`) | 會睡眠 | 保護長操作、I/O | 僅 Process Context |
| **Spinlock** (`spin_lock`) | 忙等待 (Busy loop) | 保護極短操作、硬體暫存器 | 任何 Context (含中斷) |
| **Spinlock IRQ** (`spin_lock_irqsave`) | 關中斷 + 忙等待 | **中斷與 Process 共享資料時** | 任何 Context |

### 2. 資料傳遞 (User <-> Kernel)

**絕對禁止**直接存取 User Pointer！必須使用專用 API：
-   `copy_to_user(to, from, n)`: Kernel -> User。通常用在 `read`。
-   `copy_from_user(to, from, n)`: User -> Kernel。通常用在 `write`。

## � Logic IV: DMA與硬體互動 (Direct Memory Access)

這是韌體工程師面試的**必考題**。

### 1. 為什麼需要 DMA？
CPU 不應該浪費時間在搬運資料 (memcpy)。CPU 只要告訴 DMA Controller：「把 Address A 的 4KB 搬到 Address B」，然後 CPU 去做別的事，DMA 搬完後發中斷通知。

### 2. Cache Coherency (快取一致性) ✨✨✨

```text
        CPU <--> Cache <--> DRAM
                  |
              HW (DMA)
```
DMA 直接存取 DRAM，不經過 CPU Cache。
-   **CPU 寫入 (Dirty)**：資料在 Cache 沒回 DRAM。DMA 搬運會搬到舊資料。 -> **需 Cache Flush (Clean)**。
-   **DMA 寫入 (Stale)**：DMA 更新了 DRAM，但 CPU 讀到 Cache 舊資料。 -> **需 Cache Invalidate**。

### 3. 兩套 DMA API

| 類型 | API | 特點 | 適用場景 |
| :--- | :--- | :--- | :--- |
| **Coherent Mapping** (一致性) | `dma_alloc_coherent` | 硬體/Kernel 保證一致 (Uncached) | 控制結構 (Descriptor Ring) |
| **Streaming Mapping** (流式) | `dma_map_single` | 需手動 Sync (Flush/Invalidate) | 大資料傳輸 (Network Packet) |

```c
/* Coherent: 簡單，CPU 直接讀寫 vaddr */
vaddr = dma_alloc_coherent(dev, size, &dma_handle, GFP_KERNEL);

/* Streaming: 高效，需手動 map/unmap */
dma_handle = dma_map_single(dev, buf, size, DMA_TO_DEVICE);
/* Device work... */
dma_unmap_single(dev, dma_handle, size, DMA_TO_DEVICE);
```

### 4. MMIO (Memory Mapped I/O)

存取硬體暫存器，**絕對不能**直接用指標操作 ( `*ptr = 0x1` )！
-   **原因**: Compiler 優化會亂序，CPU 會亂序。
-   **正確**: 用 `readl` / `writel`。它們包含 **Memory Barrier**。

```c
void __iomem *base = devm_ioremap_resource(&pdev->dev, res);
writel(0x1234, base + REG_OFFSET); /* 隱含 wmb() */
```

### 常用 devm_ API

| API | 用途 |
| :--- | :--- |
| `devm_kzalloc` | 分配記憶體 (自動 free) |
| `devm_ioremap_resource` | 映射暫存器 (自動 iounmap) |
| `devm_request_irq` | 註冊中斷 (自動 free_irq) |

| `devm_gpiod_get` | 獲取 GPIO (自動 put) |
| `devm_add_action_or_reset` | 註冊自定義的清理函數 |

### kmalloc Flags

| Flag | 意義 | 適用場景 |
| :--- | :--- | :--- |
| `GFP_KERNEL` | 可睡眠等待記憶體 | Process Context (Probe, Workqueue) |
| `GFP_ATOMIC` | 不可睡眠，緊急分配 | Interrupt Context, Spinlock 內 |
| `GFP_DMA` | 分配 DMA 可用的低端記憶體 | DMA Buffer |

## 📝 精選面試題 (Interview Questions)

### Q1: Platform Driver 的 probe 什麼時候被呼叫？
-   **觸發點**：當 Bus 發現有 Device (DTS Node) 和 Driver (Compatible String) 匹配時。
-   **Defer**：如果 Probe 過程中資源 (Clock/Regulator) 尚未就緒，Driver 回傳 `-EPROBE_DEFER`，Kernel 會稍後重試。

### Q2: 為什麼要有 User Space 和 Kernel Space？
-   **保護 Hardware**：防止應用程式誤改暫存器燒毀硬體。
-   **穩定性**：應用程式崩潰不會導致整個 OS 當機 (Kernel Panic)。
-   **抽象化**：提供統一 API (VFS)，隱藏硬體細節。

### Q3: copy_to_user / copy_from_user 的作用是什麼？為什麼不能用 memcpy？
-   **User 指標不可信**: User 傳來的指標可能指向無效位址，導致 Page Fault。`copy_x_user` 會檢查位址合法性並處理 Page Fault Exception。
-   **安全性**: 防止 User Space 透過傳入 Kernel 指標來讀取/修改 Kernel 內部數據 (雖然現代 CPU 有 SMAP/SMEP 保護，但 API 層面必須隔離)。
-   使用 `memcpy` 直接存取 User Pointer 是嚴重的安全漏洞。

### Q4: 什麼時候該用 Mutex？什麼時候該用 Spinlock？
-   **Mutex**: 當 Critical Section 很長，或**包含會睡眠的操作** (如 `copy_to_user`, `kmalloc`, I/O) 時使用。
-   **Spinlock**: 當 Critical Section 極短 (如修改變數、暫存器)，或**在中斷 Context** (不能睡眠) 時使用。

### Q5: container_of 是什麼？怎麼用的？
-   **用途**: 在 C 語言中，給定結構成員的指標，反推出結構本身的指標。
-   **原理**: `結構位址 = 成員位址 - 成員偏移量 (offsetof)`。
-   **場景**: 在 `inode->i_cdev` 比對後，Driver 需要拿回自己的 `struct my_device` 私有結構時使用。

### Q6: `dma_alloc_coherent` vs `dma_map_single`？
-   **Coherent**: 配置一塊 **Uncached** (或硬體維護一致性) 的記憶體。CPU 寫入立即可見。適合長期存在的控制結構 (Descriptors)。
-   **Streaming**: 使用現有 Buffer (Cached)，建立暫時映射。在 Map/Unmap 時會執行 Cache Flush/Invalidate。適合一次性大資料 (Payload)。

### Q7: 為什麼存取暫存器要用 `writel` 而不是指標？
-   **Memory Barrier**: `writel` 保證寫入順序，防止 Compiler/CPU 重排指令。
-   **Width/Endian**: 保證 32-bit 寬度與 Endianness 正確。
-   **Side Effect**: 避免 Compiler 認為寫入無用而優化刪除。
