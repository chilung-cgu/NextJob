# 🔧 指標與記憶體 (Pointers & Memory)

> **學習目標**
> 1.  建立正確的 **Memory Model** (Stack vs Heap, Address Space)。
> 2.  精通 **指標操作** (Arithmetic, Array Decay, Double Pointer)。
> 3.  掌握 **記憶體對齊 (Alignment)** 與 **Struct Padding** (NVIDIA 必考)。
> 4.  實作高階記憶體管理 (**aligned_malloc**)。

---

## 📌 Context: 為什麼 C 語言這麼危險？

C 語言給了你一把手術刀（指標），讓你直接操作記憶體。
-   **優點**：極致效能，無與倫比的硬體控制力 (韌體必備)。
-   **缺點**：沒有安全氣囊。讀錯位址 (Segfault)，忘記釋放 (Leak)，釋放兩次 (Double Free) 都是致命傷。

## 🧠 Mental Model (核心觀念圖解)

### 1. 記憶體地圖 (The Memory Map)

把記憶體想像成一條長長的街道，每個 bytes 都有一個門牌號碼 (Address)。

```text
       High Address (0xFFFFFFFF)
    ┌───────────────────────────┐
    │  Stack (向下成長)          │  ← 區域變數 (Local Vars), Return Address
    │            ↓              │
    │                           │
    │            ↑              │
    │  Heap (向上成長)           │  ← malloc/free, 動態物件
    ├───────────────────────────┤
    │  BSS (Uninitialized Data) │  ← static int x; (尚未初始化的全域變數)
    ├───────────────────────────┤
    │  Data (Initialized Data)  │  ← static int x = 10;
    ├───────────────────────────┤
    │  Text (Code Segment)      │  ← 程式碼 (唯讀)
    └───────────────────────────┘
       Low Address (0x00000000)
```

### 2. 指標的本質

指標就是一張寫著「門牌號碼」的紙條。
-   `int a = 10;` : 房子裡住著 10。
-   `int *p = &a;` : 紙條上寫著 `a` 的門牌號碼。
-   `*p` : 根據紙條上的號碼跑去那個房子，看看裡面住誰。
-   `int **pp = &p;`: 這張紙條上寫著「p 那張紙條」在哪裡。

## 🔷 Logic I: 指標基礎與算術

### 1. 指標算術 (Pointer Arithmetic)

`p + 1` 到底加了多少？取決於 `p` 指向什麼與型別 (`sizeof(*p)`)。

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;

// p 指向 0x1000 (假設)
// p + 1 指向 0x1004 (因為 int 是 4 bytes)
// p + 2 指向 0x1008
```

> **口訣**: 指標加 1，移動一個「單位」(Unit)，不是一個 byte。

### 2. 陣列退化 (Array Decay)
這是一個經典陷阱。
-   `sizeof(arr)`: 整個陣列大小。
-   `sizeof(p)`: 指標本身大小 (32-bit: 4 bytes, 64-bit: 8 bytes)。
-   **Array 傳入 Function 會退化成 Pointer**。

```c
void func(int arr[]) {
    printf("%zu", sizeof(arr)); // 8 (在 64-bit)，因為它變成 int* 了！
}
```

## 🔷 Logic II: 進階指標 (Complex Pointers)

### 1. 二重指標 (Double Pointer)
兩個用途：
1.  **改變指標本身**：如果你要在函式內改變外部指標的指向 (例如 `allocate(&ptr)` )，必須傳 `&ptr`。
2.  **動態二維陣列**：`int **matrix`。

### 2. 函式指標 (Function Pointer) & Callback
韌體開發核心模式：**將行為參數化**。

```c
/* 定義介面 */
typedef void (*handler_t)(int);

/* 註冊 Callback */
void register_irq(int irq_num, handler_t handler) {
    irq_vector[irq_num] = handler;
}

/* 實際被呼叫 */
void my_isr(int irq) { /* ... */ }
```

### 3. 指標閱讀法 (Right-Left Rule)
-   `int *p[10]`: `p` 是一個陣列 (size 10)，裡面裝 `int*` (Pointer Array)。
-   `int (*p)[10]`: `p` 是一個指標，指向一個大小為 10 的 `int` 陣列 (Array Pointer)。

## 🔷 Logic III: 記憶體對齊 (Struct Padding)

CPU 喜歡「整齊」的資料。讀取未對齊的資料 (如從 0x1001 讀 4 bytes) 可能導致效能低落或 Crash (ARM Hard Fault)。

**Padding 規則**：
1.  成員偏移量 (Offset) 必須是該成員大小的倍數。
2.  整個 Struct 大小必須是最大成員大小的倍數。

```c
struct Bad {
    char c;   // 1 byte
    // padding 3 bytes (因為 int 必須在 4 的倍數)
    int i;    // 4 bytes
    short s;  // 2 bytes
    // padding 2 bytes (因為 total size 必須是 4 的倍數)
}; // Size = 12

struct Good {
    int i;    // 4
    short s;  // 2
    char c;   // 1
    // padding 1 byte
}; // Size = 8
```

## 🔷 Logic IV: 手寫 aligned_malloc

這是頂級科技公司 (Google/NVIDIA) 的必考題。

**需求**: 實作 `malloc`，但回傳位址必須是 `alignment` (2^N) 的倍數。
**難點**: `free` 時需要知道原始位址，但使用者只會傳回對齊後的位址。

```c
void *aligned_malloc(size_t size, size_t alignment) {
    // 1. 多分配一點空間: size + alignment + 紀錄原始指標的空間
    size_t required = size + alignment + sizeof(void*);
    void *raw = malloc(required);
    if (!raw) return NULL;
    
    // 2. 計算對齊位址
    // 先留出存放 raw pointer 的空間
    uintptr_t raw_addr = (uintptr_t)raw + sizeof(void*);
    // 向上對齊公式: (x + N - 1) & ~(N - 1)
    void *aligned = (void*)((raw_addr + alignment - 1) & ~(alignment - 1));
    
    // 3. 在對齊位址的前面，偷偷藏原始指標
    ((void**)aligned)[-1] = raw;
    
    return aligned;
}

void aligned_free(void *ptr) {
    // 1. 往前看，找回 raw pointer
    void *raw = ((void**)ptr)[-1];
    free(raw);
}
```

## 📝 精選面試題 (Interview Questions)

### Q1: `sizeof(arr)` vs `sizeof(ptr)`？
-   `arr`: 陣列名。`sizeof(arr)` = 元素大小 × 元素個數。
-   `ptr`: 指標。`sizeof(ptr)` = 系統字長 (4 bytes on 32-bit, 8 bytes on 64-bit)。
-   **陷阱**: 陣列傳給函式後會退化成指標，`sizeof` 會變小。

### Q2: `void*` 是什麼？為什麼 `malloc` 回傳它？
-   `void*` 是通用指標，可以轉型成任何指標。
-   `malloc` 不知道你要存什麼，所以回傳 `void*`，讓使用者自己轉型 (C 語言中隱式轉換，C++ 需顯式)。
-   **注意**: `void*` 不能做指標算術 (標準 C 不允許，GCC 擴展允許視為 `char*`)。

### Q3: 什麼是 Dangling Pointer (懸空指標)？如何預防？
-   **定義**: 指向「已被釋放」或「無效」記憶體的指標。
    -   Ex 1: `free(p)` 後沒設 `NULL`，繼續用 `*p`。
    -   Ex 2: 回傳 Local Variable 的位址。
-   **預防**:
    -   Free 後立即設 `p = NULL`。
    -   不要回傳 Stack 變數的位址。

### Q4: 解釋 volatile 關鍵字。(驅動必考)
-   **定義**: 告訴編譯器「這個變數可能會被外部 (硬體/中斷) 改變」。
-   **行為**: 編譯器 **禁止優化** 對該變數的讀寫。每次存取都必須產生真正的記憶體 Load/Store 指令，不能只讀 Cache 或 Register。
-   **場景**:
    1.  Memory-mapped Register (硬體狀態)。
    2.  ISR 與 Main Loop 共享的 Global Flag。

### Q5: `free` 怎麼知道要釋放多少大小？
-   `malloc` 在配置記憶體時，會在回傳指標的 **前一個區塊 (Header/Metadata)** 紀錄大小。
-   `free(p)` 實際上是去看 `p - header_size` 的位置讀取長度，然後釋放。
-   這也是為什麼寫超過邊界 (Buffer Overflow) 往往會導致 `free` 時 Crash (因為 Header 被蓋爛了)。
